一直想做点自己的产品。

好几次动过念头去注册苹果开发者账号，每次都停在「算了」：Swift 要学，AppKit 要学，签名公证那一套更是一想就头大，下班之后那点精力根本撑不起来。

上周 Opus 5.5 出来，这件事突然算得过来了。智能程度、价格、稳定性都到了「非常可用」的程度；我订的是 Claude Max 20x，中秋国庆这几天这么多假期，额度用不完，于是就想，剩下的算力拿来做点自己平时要用、但现有软件给不了好体验（或者我没找到）的东西吧。

一周之后，四个住在菜单栏里的 Mac App：[Pop](https://github.com/whrss9527/pop)、[Meno](https://github.com/whrss9527/meno)、[Stox](https://github.com/whrss9527/stox)、[Proxi](https://github.com/whrss9527/proxi)。原生 Swift，玻璃质感，开源免费，全部签名公证，装上之后在 App 里一键更新。前后 130 多个版本。

<!-- 配图：主页上的四张卡片 -->

先说这四个东西是怎么来的，按我想到它们的顺序。

#### Proxi：从一个代理开关开始

源头是公司网络。连内网要设代理，Windows 上没有一个顺手的一键切换，我想要的是平时自己用不受影响，要干活了立刻连上。所以最早做的其实是个 Go 写的 Windows 托盘小工具：一个开关，切系统代理、PAC、环境变量、git、npm。

做着做着发现 Mac 上单纯切代理也不好用，就想要一个 Mac 版。但我不想要一个和 Windows 一模一样的东西：它得是原生的，主要活在菜单栏里，界面要高级一点，有玻璃的质感。这个要求后来成了四个 App 共同的调性。

然后就把平时会碰到的网络相关的事都往里加：填一个订阅地址就能选节点，全局或者按规则分流，不用再装第二个软件。我特别想要的一个场景是 PS5 和 Switch——游戏机平时得靠加速器，我想让它们直接用电脑的网络。从局域网共享，到发现游戏机上的 App 不认代理设置，再到网关模式，一步步做下来，我才意识到自己想要的是一个家庭网络的易用中枢，而不只是一个开关。

名字反而是折腾最久的。中间叫过 Kaze，连改名迁移都做完了，发布流水线正在跑，我忽然觉得它还是太像一个工具，而不是一个产品，又叫停重来。最后定了 Proxi：把 proxy 的 y 换成 i，少一个 why，多一个 I，代理应该是交到自己手里的遥控器。

#### Pop：长按右键，一划即达

这是我挂了很久的痛点。我一直想要一个全局的一键翻译；选中一段 JSON 一键格式化，Base64 一键解码，时间戳一键转换，甚至图片相关的乱七八糟的功能，都想一键搞定。之前用 uTools，相对方便，但各种功能都有额度，也不是原生的，后来只剩翻译在用，也不太好用。

这次我想清楚了交互：长按右键，鼠标旁边弹出一个圆盘，往某个方向一划，松手就执行；选中的是外文就直接翻译，是算式就直接出结果，认不出来才弹圆盘。有两点是我坚持的：松开右键圆盘就关，不要常驻；划到哪一格就临时选中哪一格，松手即点击。熟练之后不用看，肌肉记忆就够了。功能做成插件，一个 JSON 文件一个，现在有八十多个。

名字是建仓库时随手起的，释义后来才补：Pop 像泡泡，按住右键冒出来一个，往想去的方向一划，松手「啵」地破掉，事情也就办完了。

#### Stox：一眼看盘，一键隐身

应用市场里的股票软件实在不行，要收费，功能还做得一塌糊涂。我想要的是很多有用但不复杂的功能：菜单栏上看一眼，持仓盈亏自己算，到价提醒，不想看了右键一下只留个图标。

「一键隐身」是我插的一句话——Claude 最初把它理解成面板上加个眼睛按钮，我说右键就行，设置放到面板底部去。数据源选了免费、不用注册、不用 Key 的公开接口，装上就能用。

名字是 Claude 起的：stocks 六个字母压成四个，念起来还是 stocks；行情也一样，压缩成菜单栏里小小的一格。

#### Meno：菜单栏放不下了

做到这里发现一个新问题：这么多软件都占着菜单栏，MacBook 的菜单栏放多了就被刘海藏掉。GitHub 上有一个 Ice，但很久没维护了。我决定从零做一个，不去看它怎么实现的，只借鉴功能不借鉴代码，让「空白的大脑」自己发挥。

常用的留下，不常用的收起来，需要的时候点一下、悬停或者轻扫就回来；再加一个「暗格」放那些几乎用不到的图标，和按场景自动切换的规则——开会时麦克风一亮就进专注模式这种。

Meno 是意大利语「少一点」，乐谱里的 meno mosso 是「慢一点，别那么急」，而且和 Menu 只差一个字母。

#### 学到的

- 说清品类和一个交互约束，把设计交出去。四个起点都是一两句话，设计文档我一份都没评审过，只验收产品。
- 给参照物，不给方案。「参考我另一个仓库」「参考某知名仓库」。自己的旧仓库是最好的规格说明。
- 自己当第一个用户。真机上的问题 CI 永远测不出来，但我报完之后，CI 可以把它变成测试。
- 放权是阶梯式的。先逐次批准合并，再一句「持续发布」，然后它自己加闸门，最后工具层还有权限分类器兜底。它没有绕过任何一道。
- 规则要写进仓库。口头说的只在一个窗口生效——我在 Pop 的窗口说了「请你总是回复中文」，同一天另一个窗口照样飘成英文。写进 CLAUDE.md 的，续接之后和另一个窗口都遵守。
- 最花时间的反而是小事。DNS、token 的权限——这些都是只有我能动手的。

#### 代价

真正的成本是额度：一周的额度两天半用到了 92%，写这篇的大纲时真的撞上了每周上限。如果按 API 标价折算，这一周大概是三千多美元，无人值守时七到十三美元一个版本。

#### 写在最后

四个 App 都在 GitHub 上，免费开源，README 里有下载链接，Homebrew 这两天也会好。它们都很新，功能加得快，打磨得还不够，用着有什么不对的，欢迎提 issue，或者直接告诉我。

回头看，这一周最大的变化不是做出了四个 App，而是「做产品」这件事从「等我有精力学会了再说」变成了「想清楚要什么，然后开始」。以前卡在学习成本上的那堵墙没了，剩下的东西反而更像产品本身：知道自己的痛点在哪，坚持几个交互上的判断，当第一个用户，愿意为签名公证这种麻烦事花钱花时间。这些 AI 都替不了，也正好是我喜欢做的部分。

下一个想做的，想法池里已经排着了。
